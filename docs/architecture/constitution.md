# DANI engineering constitution

1. DANI owns one canonical job and effect lifecycle; Hermes owns open-ended reasoning, not authorization.
2. Every side effect crosses one typed broker with identity, preconditions, approval scope, idempotency/reconciliation and evidence.
3. Dispatch is not success. Terminal success requires adapter-specific verification. Ambiguous outcomes are `UNKNOWN`, never blindly retried.
4. Exact stop/status/auth and crash recovery work without a model. Speech interruption and task cancellation are separate commands.
5. Laya is advisory, schema-bound and shadow-only until measured promotion criteria pass. It never grants permission.
6. Memory is derived, scoped, attributed and deletable. Jobs and live external state remain authoritative.
7. Provider selection is capability-aware and never silently incurs cost, borrows credentials or degrades security.
8. One lease controls each physical desktop. Parallel work uses isolated resources, not competing clicks.
9. External content is untrusted data. Prompts, pages and tool output cannot widen authority.
10. Claims require reproducible evidence. Failed or unrun tests remain failed or unverified.
